# 介護職向け 動物タイプ診断アプリ 作成考慮案

> 2026-10-23 に作者から受け取った資料を、そのまま Markdown にしたもの。
> 要件定義書の前段階として、作りたいものの考え方・決めたこと・まだ決まっていないことをまとめた資料。
> この資料の内容から変わった点は `docs/02_requirements.md` が正とする。

## 1. 目的

- チーフ・リーダーが、自分の「リーダーとしてのタイプ」を知り、どう成長すればよいかの方向を見つける
- スタッフ一人ひとりの性格と得意・苦手を知り、関わり方・任せ方・教え方に活かす
- 上司と部下、スタッフ同士の相性と、うまくいく関わり方のコツがわかるようにする
- 介護現場の仕事に合わせつつ、一般的なビジネススキルも見えるようにする
- 動物キャラクターを使い、楽しく・わかりやすく・職場で話題にしやすくする

## 2. 使う人と使い方

| 使う人 | 使い方 |
|---|---|
| チーフ・リーダー | 自分のリーダータイプを知る。部下の結果を見て関わり方を考える |
| 一般スタッフ | 自分のタイプと得意・苦手を知る。上司や同僚との関わり方の参考にする |
| 研修担当 | 新人研修やチームづくりの研修で、話し合いの材料として使う |

## 3. 全体のしくみ

- 質問は「性格」「介護スキル」「ビジネススキル」をまぜて出す（答える人は区別を意識しない）
- 結果は一つの動物キャラとして表示する
- 動物と型は性格パートで決める（16の動物 × どっしり型・こまやか型 ＝ 32タイプ）
- スキルパートの結果は動物に「肩書き」としてつける
  - 例：「入浴マスターのライオン・こまやか型」「家族対応の達人のイルカ・どっしり型」
- 結果ページは中身ごとに分けて表示する（性格／長所・短所／リーダー・部下として／相性／スキル）

スキルの好き嫌いまで動物を決める材料にすると、タイプの意味がぶれやすくなるため、動物＝性格、肩書き＝スキルと役割を分ける。

## 4. 性格パート（32タイプ＝16の動物×2つの型）

性格の軸は、心理学でいちばん裏づけのある「ビッグファイブ（5因子モデル）」に合わせて5本にする。5本の組み合わせで32タイプになる。

### 4-1. 5本の軸

| 軸 | 左側 | 右側 | もとになる性格特性 | 何がわかるか |
|---|---|---|---|---|
| A：関わり方 | 引っぱる（L） | 支える（S） | 外向性 | 前に立つか、後ろから支えるか |
| B：見るところ | 成果を見る（T） | 人を見る（H） | 協調性 | 仕事の結果を重く見るか、気持ちや関係を重く見るか |
| C：進め方 | 計画的（P） | 臨機応変（F） | 誠実性（まじめさ） | 段取りを決めて進めるか、状況に合わせて動くか |
| D：変化への姿勢 | 決まりを守る（K） | 新しく変える（N） | 開放性 | 今のやり方を守るか、より良く変えるか |
| E：気持ちの安定 | どっしり（D） | こまやか（M） | 情緒安定性 | 気持ちがゆれにくいか、小さな変化に敏感か |

- A〜Dの4本で16の動物を決め、E軸は「型」として表示する（例：ライオン・どっしり型／ライオン・こまやか型）
- タイプ名は入口で、本体は5本の軸の「何％寄りか」のスコア（研究では、タイプに分けるより連続したスコアの方が信頼できるため）
- 50％に近い軸は「どちらもできるバランス型」と表示する
- こまやか型は短所として書かない。介護では利用者の小さな変化に気づく強みになる
- タイプコードの例：LTFK-D（ライオン・どっしり型）

### 4-2. 軸ごとの長所と短所（長所を生かし、短所は補う）

| 軸の側 | 長所 | 短所になりやすいところ | 補い方 |
|---|---|---|---|
| 引っぱる | 方針を示し、迷う場面で決められる | 一人で決めてしまい、意見を聞きもらす | 決める前に「どう思う？」と1人に聞く |
| 支える | 周りをよく見て、目立たない仕事も引き受ける | 意見を言わずにためこむ | 会議の前に意見をメモしておく |
| 成果を見る | 目標や期限を守り、業務を回せる | 気持ちへの配慮が後回しになる | 指示の前にひとことねぎらう |
| 人を見る | 利用者や仲間の気持ちをくみ取れる | 注意したり断ったりするのが苦手 | 「事実＋お願い」の形で伝える |
| 計画的 | 段取りがよく、ミスが少ない | 予定外のできごとに弱い | 予備の時間とプランBを用意する |
| 臨機応変 | 急な変化にも合わせられる | 記録や準備が後回しになりやすい | 締め切りをチェックリストにする |
| 決まりを守る | 手順を守り、安全で安定したケアができる | 新しいやり方に抵抗を感じやすい | 小さく1回だけ試してみる |
| 新しく変える | 改善のアイデアを出せる | 周りを置いていきやすい | 変える理由と手順をセットで説明する |
| どっしり | 緊急時も落ち着いて動け、周りを安心させる | 人の不安や小さな変化に気づきにくい | 「最近どう？」と定期的に声をかける |
| こまやか | 利用者や職員の小さな変化に気づける | 心配しすぎて疲れやすい | 気づいたことを一人で抱えず相談する |

32タイプそれぞれの説明は、この表の長所・短所・補い方を組み合わせて作る。

### 4-3. 4つのグループ（A軸×B軸）

| グループ | 組み合わせ | ひとことで |
|---|---|---|
| けん引グループ | 引っぱる × 成果 | 目標に向かってチームを動かす |
| まとめ役グループ | 引っぱる × 人 | みんなを巻き込み、雰囲気をつくる |
| 職人グループ | 支える × 成果 | 確実な仕事でチームを支える |
| 寄りそいグループ | 支える × 人 | 利用者や仲間の気持ちに寄りそう |

B軸はPM理論の「成果を出す力（P）」と「人をまとめる力（M）」に対応する。研究でも、リーダーの性格は「段取りづくり」と「配慮」という2つの行動を通して成果につながるとされている（17章）。

## 5. 介護スキルパート

### 5-1. 項目案

| 分類 | 項目 |
|---|---|
| 生活の介助 | 食事介助／排泄介助／入浴介助／移乗・移動介助／着脱・整容 |
| 関わり | 認知症の方への関わり／利用者との会話／家族への対応 |
| 企画・前に出る | レクリエーションの企画／人前に立って進行する |
| 作業 | 黙々とした作業（掃除・準備・片付けなど）／記録 |
| 検討中 | 看取りケア／夜勤／緊急時の対応 |

### 5-2. 「好き」と「得意」を分けて聞く

- 1つの項目について「好き（やりたい）」と「得意（できる）」の2つを答えてもらう
- 組み合わせで意味が変わる

| 好き | 得意 | 読み取り方 |
|---|---|---|
| 高い | 高い | 強み。任せると力を発揮する |
| 高い | 低い | 伸びしろ。教えるとぐんと伸びやすい |
| 低い | 高い | できるが負担を感じている可能性。任せすぎに注意 |
| 低い | 低い | 支えが必要。ペアで行うなど工夫する |

## 6. ビジネススキルパート

| 項目 | 例となる質問のイメージ |
|---|---|
| 上司への報告・相談 | 困ったとき、すぐ上司に相談できる |
| 電話対応 | 電話に出るのは苦にならない |
| パソコン・記録作業 | パソコンでの入力や書類づくりが好き |
| 時間管理・段取り | 仕事の順番を考えて動ける |
| 後輩への教え方 | 後輩に説明するのが好き |
| 他職種との連携 | 看護師やケアマネに自分から声をかけられる |
| 会議で意見を言う | 会議で自分の考えを話せる |
| 急な変更への対応 | 予定が急に変わっても落ち着いて動ける |

## 7. 肩書きのつけ方

- 介護スキル・ビジネススキルのうち、「好き」と「得意」の両方が高い項目を1つ選んで肩書きにする
- 例：「入浴マスター」「家族対応の達人」「段取り名人」「黙々職人」「レクの盛り上げ役」
- 同点のときの決め方、全体的に低いときの肩書き（例：「これから伸びる〇〇」）は今後決める

## 8. 質問の量と答え方

- 目標：合計70問前後、15分前後で終わる量
- 性格パート：40問（1軸あたり8問）。逆向きの質問もまぜて、なんとなくの回答を見分ける
- スキルパート：約20項目。1画面で「好き」「得意」を一緒に答える形にして負担を減らす
- 答え方：5段階（そう思う〜そう思わない）。真ん中ばかり選ばれないよう、6段階にする案も検討
- 介護現場の場面を使った質問を多めにする（例：「急に利用者さんが転びそうになったとき、まず体が動く」）
- 検討案：「かんたん版（約35問・7分）」と「くわしく版（約70問・15分）」を選べるようにする
- 途中で保存して、あとから続きができるようにする

## 9. 結果ページの構成案

1. キャラ表示：肩書き＋動物＋型（例：入浴マスターのライオン・こまやか型）、ひとことの説明
2. 性格タイプ：5本の軸の％グラフ、性格の特徴
3. 長所と短所：軸ごとの長所、短所になりやすいところ、補い方
4. リーダーとして：強み、気をつけたいクセ、成長のためのヒント、短所を補ってくれる相手のタイプ
5. 部下として：強み、伝わりやすい指示の出し方、やる気が出る声かけ
6. 相性：合いやすいタイプ、ぶつかりやすいタイプ、補い合えるタイプ、関わり方のコツ
7. 介護スキル：レーダーチャート（好き・得意の2本線）、強みと伸びしろ
8. ビジネススキル：レーダーチャート、強みと伸びしろ
9. まとめ：明日からできること3つ

## 10. 相性の考え方

- 32×32＝1,024通りの文章を全部書くのは無理なので、軸ごとのルールから組み立てる
  - 同じ側どうし：話が早い。ただし同じところを見落としやすい
  - 反対側どうし：補い合える。ただし考え方の違いでぶつかりやすい
- 一方の短所を、もう一方の長所が補える組み合わせを「補い合いペア」として表示する
- 上司→部下、部下→上司、同僚どうしで見せ方を変える
  - 例：上司が「臨機応変」、部下が「計画的」なら「指示は早めに、変更は理由をそえて伝える」

## 11. チーム機能（第2段階で検討）

- チーフが部下の結果を一覧で見られる
- チーム全体のタイプの割合、スキルの偏りを表示する（例：入浴が得意な人が少ない）
- 2人を選んで相性を見る

## 12. 注意すること

- 正式な心理検査ではなく、自分を知るきっかけ・話し合いの材料であることを画面に書く
- 人事評価には使わないことをはっきり書く
- 結果を上司に見せるかどうかは本人が選べるようにする
- タイプで人を決めつけない言い方にする（「〜な傾向があります」など）
- 苦手が多い人でも落ち込まない、前向きな書き方にする

## 13. 画面とデザイン

- スマホで答えることを一番に考える（休憩中などにも答えやすく）
- 読みやすさの設定：BIZ UDPゴシック、クリーム色の背景、広い行間
- 動物イラストはやわらかく親しみやすいタッチ
- 漢字にはなるべくふりがなを付けられるようにする（外国人スタッフへの配慮）
- 結果は画像として保存・共有できるとよい

## 14. 技術構成の案

| 段階 | 内容 |
|---|---|
| 第1段階 | HTML／CSS／JavaScript（または React＋Vite）の静的サイト。結果は端末の中に保存 |
| 公開 | GitHub Pages など |
| データ管理 | 質問・タイプの説明文・相性ルールを JSON ファイルで管理し、プログラムと分ける |
| 第2段階 | チーム機能のためにログインとデータ保存（Supabase など）を検討 |
| 開発の進め方 | Git で管理し、Claude Code・Codex で作成。質問や文章の修正はJSONだけ直せばよい形にする |

## 15. 進め方の案

1. 軸・動物・スキル項目を決める
2. 質問文をつくる（性格40問＋スキル約20項目）
3. 軸ごとの長所・短所、32タイプの説明文、相性ルールをつくる
4. 試作品（診断→結果表示）をつくる
5. 職場の数人に試してもらい、感想を集める
6. 質問・文章・判定の調整
7. チーム機能の検討

## 16. まだ決まっていないこと（資料作成時点）

- 動物16種類の最終決定と、イラストの用意方法
- アプリの名前
- 答え方を5段階にするか6段階にするか
- かんたん版・くわしく版を分けるか
- 看取り・夜勤・緊急時対応を項目に入れるか
- 肩書きの種類と決め方のルール
- 結果をどこまで上司と共有するか
- 名前を入れずに使えるようにするか

## 17. 根拠にした研究と考え方

- ビッグファイブ：性格を5つの大きな軸で表す考え方で、心理学で広く研究され、確かめられている
- Judgeほか（2002）のまとめ研究：外向性と開放性が、リーダーとして選ばれることとリーダーの効果の両方に一貫して関係していた
- 2024年 Journal of Applied Psychology のまとめ研究：リーダーに選ばれること（120サンプル、32,579人）と効果（116サンプル、42,487人）を分析。集団のつながりを大切にする文化では、外向性と協調性がリーダーの効果を特に強く予測する。外向性・協調性は「配慮」を通して、誠実性などは「段取りづくり」を通して効果につながる
- PM理論・ソーシャルスタイル：わかりやすく伝えるための補助として使う
- MBTIのような2つに分けるタイプ診断：学術的な裏づけが弱いと一般に指摘されている。このため、％スコアを本体にし、タイプは入口として使う

※検索結果の要約をもとにした整理。要件定義書にする前に原文を確認する。

## 19. 最初に送るプロンプト案（資料の作業ルール部分）

作業ルール：

- 画面の文字は日本語で、中学生にわかる言葉にする
- フォントはBIZ UDPゴシック、背景はクリーム色、行間は広め
- スマホで使うことを一番に考える
- 質問・説明文・相性はすべて data/ のJSONで管理し、コードに直接書かない
- 結果は端末の中（localStorage）だけに保存し、外部に送らない
- 1つの作業が終わるごとにコミットし、何をしたか日本語で説明する

3回目以降は「質問を40問にふやす」「結果ページに相性を足す」のように、1回に1つずつ頼む。
