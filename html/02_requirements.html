〖0〗 ひとことで言うと

40問に答えると、動物のキャラで自分のリーダータイプがわかる Web アプリです。

結果では、長所と「のびしろ」、リーダー・部下としての特徴を読めます。
さらに、のばしたいところを自分で選ぶと、半年分の成長ステップが出ます。

回答は自分のスマホの中だけに保存し、どこにも送りません。

〖2〗 なぜ作るのか

介護現場のリーダーが、リーダーシップをもっと発揮したいと考えたとき。
まず自分のリーダータイプを見きわめ、長所を生かして短所を補う方針を立てられるようにします。 〔ゆ〕

◇ 誰が使い、どう広がるか 〔ゆ〕

  1. 作った本人（一番の利用者）
  2. 職場のスタッフ … 「おもしろいから答えてみて」と誘う範囲。評価とは切り離す
  3. インターネットで一般公開 … おもしろければ、介護職の人なら誰でも使えるように

◇ 成功の基準 〔ゆ〕

  • 〇 当たっていると感じる
  • 〇 読んだあとに前向きになり、やる気が上がる
× これをしたら失敗（動いていても）
  • 読んだ人が落ち込む、「決めつけられた」と感じる
  • 人事評価の道具として使える形になる
  • 回答や結果が外部に送られる
  • 文字が小さい・つまっている・色だけで区別しているなど、読みにくい

バランス型

〖4〗 診断のしくみ

◇ 点数の計算 〔C〕

  1. 答えを 1〜5 の数にする（「そう思わない」＝1 … 「そう思う」＝5）
  2. 右側に寄る質問はそのまま、左側に寄る質問は 6 − 答え にする
  3. 軸ごとに平均して、(平均 − 1) ÷ 4 × 100 で右側寄り度（0〜100）にする
  4. 50 未満なら左側、50 以上なら右側の文字を使う
  5. 画面には、寄っている側の％を出す（例：右側寄り度 28 → 「引っぱる 寄り（72％）」）
  6. 40〜60 なら「◎ バランス型（どちらもできる）」と表示する。動物と型の判定は 4. のまま
《 参考 》

1軸8問・5段階なので、点数は 3.125 きざみになります。40 と 60 ちょうどの点は出ません。

◇ イラスト：絵柄D「シンプルゆるかわ」 〔ゆ〕

  • 介護職員のポロシャツと無地の名札。制服の色はグループの色 〔C〕
  • 性別・年齢を感じさせないデザイン
  • キラキラ・ハート・葉っぱなどのあしらいも同じ絵柄で作り、ページに散りばめる

◇ 色 〔ゆ〕

  • アプリ全体の土台：案A「コーラル × ミント」
  • キャラの色はグループごとに4色。一人の結果に出るのは1色
  • 5本の軸は色で分けず、アイコンで見分ける（例：関わり方＝🚩、見るところ＝👀）
グループ色の案 〔C〕見本
けん引コーラル コーラル
まとめ役ひまわりイエロー ひまわりイエロー
職人ミント ミント
寄りそいラベンダー ラベンダー

4色とも、ライト・ダークの両方で文字と背景のコントラスト 4.5:1 以上を測って決めます。

◇ 読みやすさ（LD・ディスレクシア対応） 〔ゆ〕

  • 〇 文字は大きめ：本文 18px（スマホ）／19px（タブレット）／20px（パソコン）。15px 未満は使わない
  • 〇 行間 1.85、文字の間 0.04em、左そろえ、斜体なし、1行は約34文字まで
  • 〇 色だけで区別しない（記号・枠・太字・バッジをいっしょに使う）
  • 〇 真っ白・真っ黒を使わない。押すところは 44px 以上
  • 〇 ダークモードと「動きを減らす」設定に対応
  • 〇 本文は教科書体（ディスレクシア対応） 〔ゆ〕。見出し・ボタン・数字は BIZ UDPゴシック 〔C〕

〖9〗 イラストの作り方

  1. 動物16種の一覧を、作者に確認してもらう

〖10〗 なぜこの作り方か（第三者への説明用）

「なぜこの道具で、この方法で作っているのか」を、中学生にもわかる言葉でまとめます。
人に説明するときは、この章をそのまま使えます。

① なぜ「静的サイト」なのか

◇ たとえ：パンフレットを置くか、受付の人を置くか

静的サイトは、印刷したパンフレットを置いておくようなものです。
サーバーで動くプログラムは、受付の人がその場で答えを書いて渡すようなものです。
受付の人がいると、そこが狙われます。パンフレットなら、狙われる場所がほとんどありません。

作り方〇 良いところ△ 困るところ
静的サイト（今回）無料・速い・攻撃される場所がほぼない・回答を外に送らないと言い切れるみんなのデータを集めることはできない
PHP・WordPress などのサーバーデータを集めたり、ログインを作ったりできる受付（サーバー）が狙われる。修正が出るたびに更新が必要。お金がかかる
スマホアプリスマホの機能をフルに使えるストアの審査がある。iPhone 用と Android 用の2つが必要
診断メーカー・Google フォームすぐ作れる見た目や判定のしくみを自由に作れない

診断の計算はスマホの中だけでできるので、受付の人（サーバー）はいりません。
回答がどこにも送られないので、「人事評価には使わない」という約束にも一番安心です。

② なぜ GitHub Pages で公開するのか

  • 〇 静的サイトを無料で公開できる。暗号化（https）も最初からついている
  • 〇 設計図（コード）の保管場所と公開場所が同じ。直したら、そのまま公開できる
  • △ 比べた相手：レンタルサーバー（お金がかかり、サーバーの更新も自分の仕事になる）、Vercel など（同じくらい便利だが、GitHub だけで済むほうがシンプル）

③ なぜ Vite ＋ TypeScript なのか（React は使わない）

道具たとえ選んだ理由
TypeScript書いている途中で赤ペンを入れてくれる先生「数字のところに文字を入れた」などの間違いを、動かす前に教えてくれる。AI が書いたコードの間違いも見つけやすい
Vite組み立て工場書いたコードを、スマホで速く動く形にまとめる。今いちばん広く使われている道具のひとつ
React（使わない）大きな工場の機械画面がたくさんある大きなアプリ向け。このアプリは画面が3つほどなので大きすぎる。部品が少ないほど、守る場所も少ない

④ なぜ質問や文章を JSON に分けるのか

◇ たとえ：台本と役者を分ける

質問や説明文（台本）を、プログラム（役者）から切り離します。
文章を直したいときは台本だけを直せばよく、プログラムを壊す心配がありません。

⑤ なぜテスト（Vitest）を書くのか

「この答え方なら、ライオン・どっしり型になるはず」を、自動で確かめるしかけです。
質問を増やしたり計算を直したりしても、判定が狂っていないことをいつでも確かめられます。

⑥ なぜ pnpm なのか

部品（パッケージ）をそろえる係です。npm より速く、パソコンの容量を食いにくい。
新しすぎる部品はすぐに使わないなどの安全の設定が強めで、〖11〗の攻撃に強くなります。

〖11〗 セキュリティとプライバシー

希望：脆弱性はしっかりつぶす。 〔ゆ〕

△ PHP の修正（2026年10月）について

このアプリは PHP を一切使いません。サーバーでプログラムを動かさない静的サイトなので、PHP の脆弱性の影響を受けません。

対策内容
外部に送らない回答と結果は端末の中（localStorage）だけ。アクセス解析・広告・外部フォント・外部スクリプトを入れない
Vite の版8.0.16 以上。CVE-2026-53571（Windows で .env などが見えてしまう問題）などの修正版
開発用サーバー自分のパソコンの中だけで動かす。ネットワークに出さない
pnpm の設定公開から24時間たっていない部品は入れない。部品が勝手にプログラムを実行するのを止める。公式の説明で確かめてから設定する
部品の固定pnpm-lock.yaml で版を固定する
見張りGitHub の Dependabot と pnpm audit で、部品の脆弱性を自動で知らせる
画面への書き出し文章を innerHTML に流しこまない
読み込みの制限（CSP）自分のサイト以外からの読み込みを禁止する
秘密のファイル.gitignore に .env*・*.pem・*.key などを入れる

〖12〗 公開のしかた 〔ゆ〕

  • 〇 v1 のゴール：GitHub Pages に載せ、スマホで使えるところまで。職場の人にもこの URL で配る
  • 〇 リポジトリは公開（無料プランで GitHub Pages を使うため）
  • 〇 そのため、リポジトリに入れる文書には個人の事情を書かない
  • 〇 一般公開までは、検索エンジンに載らない設定にする
  • 〇 GitHub 上でリポジトリを作る・公開する操作は、作者の確認をとってから行う
